# RD §15.6 negative-control adjudication procedure

Operational continuation of the frozen §15.6 rule. This adds no measurement semantics and does not
modify the frozen candidate generator, charter, matcher, vocabulary, or truth tooling.

## Fixed inputs

- Only the five three-way-admissible fixtures in `C4-REPORT.md` participate.
- Candidate order is generated by the frozen `negative_control.py`; the exact output is committed in
  `manifest.yaml` before any negative-control author label or judge run.
- The source CWE is the top-level weakness named by the fixture's already-frozen claim. SiYuan uses
  CWE-200 (information exposure; CWE-22 is the mechanism), Vikunja uses CWE-862 (the frozen claim,
  rather than advisory alias CWE-639), LiteLLM uses CWE-918, and Mnemosyne uses CWE-347. The DHCP
  claim's named denial-of-service effect maps to CWE-400, the corresponding member of the frozen
  substitution list.
- Candidate claims use the unchanged §15.5 task shape: “in `<package>`, attacker-controlled input may
  lead to `<candidate CWE name>`.” They are package-wide existential claims, not silently narrowed
  to the real fixture's known path.

## Evidence contract

Each fixture is adjudicated as one batch containing its three candidates in frozen order. The author
and judges receive the same candidate wording and canonical `vuln`/`fixed` revisions. Judges receive
only the frozen `judge-prompt.md`; they do not receive author labels, real-truth keys, selection
reasoning, project chat, or another judge's output.

The prompt may contain only factual evidence:

1. the real fixture's already-frozen advisory evidence, execution evidence, product fix diff, and
   code contexts;
2. a complete tracked product-source path inventory for both revisions;
3. deterministic, candidate-specific source scans over that inventory, with the exact regex,
   number of matching lines, and sorted matches (or an explicit truncation marker);
4. short source excerpts needed to understand a scan match.

Product-source inventory means `.go` excluding `_test.go`, `vendor/`, and `testdata/` for Go; `.py`
excluding path components `test`, `tests`, `.venv`, `venv`, `build`, and `dist` for Python. Generated
product source remains included. Search evidence is diagnostic, not a proof by itself: a match does
not establish a CWE, and no match is enough for `NOT_SUPPORTED` only when the inventory and package
surface make the missing primitive dispositive. Otherwise the label is `INDETERMINATE`.

## Independent labels and selection

Before either judge sees the prompt, the author freezes one label per candidate per revision:

- `SUPPORTED`: evidence establishes at least one instance of the substituted package-wide claim;
- `NOT_SUPPORTED`: evidence establishes that the substituted claim is false in that revision;
- `INDETERMINATE`: neither conclusion is justified by the evidence.

The two judges independently use the same three labels. They may add a concise rationale but may not
change candidate order or wording. Reconciliation is mechanical:

1. a candidate qualifies only if author, Judge A, and Judge B all label **both** revisions
   `NOT_SUPPORTED`;
2. the first qualifying candidate in frozen order becomes the fixture's negative control;
3. if none qualifies, the fixture has no negative control;
4. no candidate is rerun, rewritten, or replaced after judge output.

Judge A and Judge B use the already-frozen isolated harness identities (`gpt-6.1-sol` and
`deepseek/deepseek-flash`) and a byte-identical prompt. Raw transcripts are retained. A trailing
Markdown fence may be removed only from the structured copy; raw output remains unchanged.

## Output schema

```yaml
labels:
  candidate-01: {vuln: NOT_SUPPORTED, fixed: NOT_SUPPORTED}
  candidate-02: {vuln: INDETERMINATE, fixed: INDETERMINATE}
  candidate-03: {vuln: SUPPORTED, fixed: SUPPORTED}
```

This procedure is frozen before author assessment or judge execution.
